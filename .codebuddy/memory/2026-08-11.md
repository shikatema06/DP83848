# 2026-08-11

## Bootloader 不跳 App 问题排查

- 现象：Bootloader 启动后 `should_jump = 0`，无法跳转到 Slot A 的 App。
- 调试发现：`iap_slot_validate()` 中 `cal != meta->img_crc32`。
- 根因：使用 HEX 文件烧录 App 时，Intel HEX 默认不输出全 0 的填充区域，导致 Flash 里对应位置保持 `0xFF`，而 `DP83848.bin` 里是 `0x00`。两者仅有 8 字节差异，但 CRC 校验失败。
- 修复：修改 `.vscode/flash_both.cmd`，App 改用 `DP83848.bin` 按地址 `0x08010000` 烧录（`ST-LINK_CLI -P DP83848.bin 0x08010000 -V`），脚本中增加从 ELF 自动生成 bin 的步骤。
- 验证：OpenOCD dump Flash App 区域后与 `DP83848.bin` 完全一致，CRC 均为 `0x57644256`。
- 为加快调试，临时将 Bootloader 跳转超时从 60 秒改为 5 秒（`Bootloader/bootloader_main.c` 第 140 行），并重新编译烧录。
- 修复 `jump_to_app()`：加 `__disable_irq()`、清理 NVIC ICER/ICPR、停 SysTick、`__DSB()/__ISB()` 屏障、扩大 SP 检查范围到 `0x20030000`。
- 修复 LwIP `LWIP_RAND` 问题：`arch/cc.h` 无条件定义 `LWIP_RAND` 覆盖了 `lwipopts.h`，导致 `udp_init()` 调用 newlib `rand()` 触发 HardFault。修改 `arch/cc.h` 加 `#ifndef LWIP_RAND` 保护。
- 修复后新 fault：`sys_timeouts_init → sys_timeout → sys_timeout_abs` 中访问 `next_timeout->time` 时 BusFault。`bfar = 0x276E6F68`（非法地址），`MEMP_NUM_SYS_TIMEOUT = 1` 来自默认值，Bootloader 至少需要 1 个 ARP timer。
- 后续：需继续验证 Bootloader 5 秒超时后能否正确 `jump_to_app()`，以及跳转前是否需要关闭中断、清理 NVIC 等健壮性处理。
