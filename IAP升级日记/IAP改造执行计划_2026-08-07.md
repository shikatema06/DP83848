# IAP 改造执行计划

> 日期：2026-08-07
> 目标：完成 Bootloader/App 侧旧 `boot_valid` 逻辑向 `iap_slot` 的迁移
> 用途：按本计划逐项执行，即可得到可编译、可运行的 A/B 双备份升级流程

---

## 一、今日改造范围

1. `Bootloader/bootloader_main.c`：用 `iap_slot` 替换旧的 `boot_valid` 启动决策。
2. `Bootloader/tftp_server.c`：把新固件写入动态 spare 槽，传输完成后调用 `iap_slot_mark_new`。
3. `Core/Src/tcp_echoserver.c`：CMD_ENTER_BOOTLOADER 使用 `FLASH_If_Write_Boot_Request(UPGRADE)` + `NVIC_SystemReset()`。
4. `Bootloader/CMakeLists.txt`：添加 `iap_slot.c` 到构建源文件。

---

## 二、改造前确认

确保 `iap_slot.h` / `iap_slot.c` 已完成并位于 `Bootloader/` 目录。

确认 `flash_if.h` 中已定义：

- `BOOT_REQUEST_ADDR`
- `BOOT_REQUEST_UPGRADE`
- `BOOT_SLOT_ADDR`
- `SLOT_A_START_ADDR` / `SLOT_B_START_ADDR`
- `FLAG_SECTOR_START_ADDR`

## 三、步骤 1：修改 `Bootloader/bootloader_main.c`

### 3.1 添加头文件包含

在文件顶部 `#include` 区域加入：

```c
#include "iap_slot.h"
```

### 3.2 删除固定 App 地址宏

删除或注释掉：

```c
#define APP_START_ADDR  0x08010000U
```

后续跳转地址由 `iap_slot_start_addr(active_id)` 动态提供。

### 3.3 修改 `jump_to_app()` 为带参数版本

将函数签名从：

```c
static void jump_to_app(void)
```

改为：

```c
static void jump_to_app(uint32_t app_addr)
```

函数内部：

- 把所有 `APP_START_ADDR` 替换为 `app_addr`。
- 读取初始 SP 和 PC 时使用 `app_addr` 和 `app_addr + 4U`。
- `SCB->VTOR = app_addr`。

### 3.4 修改 `main()` 的启动决策逻辑

#### 原逻辑删除

删除以下旧代码：

```c
uint32_t boot_valid;
int       app_exists;

boot_valid = *(volatile uint32_t *)BOOT_VALID_ADDR;
app_exists = (boot_valid == BOOT_VALID_MAGIC);
```

#### 新逻辑插入

在 `HAL_Init()` 之后、`Boot_LWIP_Init()` 之前插入：

```c
iap_slot_init();
```

然后在 LwIP 初始化之前，构造启动决策：

```c
boot_slot_id_t active_id    = iap_slot_get_active();
uint32_t       active_addr  = iap_slot_start_addr(active_id);
uint32_t       boot_request = *(volatile uint32_t *)BOOT_REQUEST_ADDR;
int            should_jump  = 0;

if (boot_request == BOOT_REQUEST_UPGRADE) {
    /* App 明确要求升级：留在 IAP 模式 */
    should_jump = 0;
} else if (iap_slot_validate(active_id) == SLOT_IMG_VALID) {
    /* 有合法 active 槽：60 秒超时后跳转 */
    should_jump = 1;
} else {
    /* 没有合法 active 槽：只能等待升级 */
    should_jump = 0;
}
```

### 3.5 修改主循环

把原来的：

```c
if (app_exists) {
    ...
    jump_to_app();
    app_exists = 0;
}
```

改为：

```c
if (should_jump) {
    if (IAP_tftpd_has_activity())
        continue;

    if (HAL_GetTick() - iap_start_tick >= 60000U) {
        jump_to_app(active_addr);
        /* 跳转失败（SP 非法），降级为永久 IAP 模式 */
        should_jump = 0;
    }
}
```

### 3.6 可选：更新 fault_capture

当前结构体字段 `boot_valid_value` 含义已过时。可改名为 `boot_slot_word` 并在 `main()` 启动时记录：

```c
f->boot_slot_word = *(volatile uint32_t *)BOOT_SLOT_ADDR;
```

或者新增 `active_slot_id` 字段记录 `active_id`。

## 四、步骤 2：修改 `Bootloader/tftp_server.c`

### 4.1 升级目标地址动态化

找到当前固定写入 `SLOT_A_START_ADDR`（或 `APP_START_ADDR`）的位置。

在 WRQ（写请求）处理函数中：

1. 调用 `iap_slot_get_spare()` 获取备用槽编号。
2. 调用 `iap_slot_start_addr(spare_id)` 获取写入基址。
3. 把该基址保存到 TFTP 状态结构体中，作为后续数据包写入地址。

### 4.2 传输完成后标记新镜像

在最后一个数据包处理完成后：

1. 统计实际接收到的总字节数 `total_len`。
2. 计算 CRC32：
   - 可以复用 `iap_slot_calc_crc(spare_id)` 在传输完成后计算。
   - 也可以边传边算，最后直接比较。
3. 调用：

```c
iap_slot_mark_new(spare_id, total_len, image_crc);
```

### 4.3 触发提交（可选策略）

根据产品策略选择：

**策略 A：TFTP 完成后立即 commit（自动切换 active）**

在 `mark_new` 成功后调用：

```c
iap_slot_commit(spare_id);
```

然后延时或立即 `NVIC_SystemReset()`，让 Bootloader 从新槽启动。

**策略 B：TFTP 只 mark_new，由上位机单独命令 commit**

如果希望人工确认后再切换，可以增加一个 TFTP 命令或 TCP 命令，在收到 commit 指令后再调用 `iap_slot_commit(spare_id)`。

本次改造建议先用**策略 A**，流程最简单。

## 五、步骤 3：修改 `Core/Src/tcp_echoserver.c`

### 5.1 找到 CMD_ENTER_BOOTLOADER 处理分支

在 TCP 命令解析中找到进入 Bootloader 的分支。

### 5.2 替换旧的跳转/复位逻辑

原逻辑可能是直接跳转或设置标志。改为：

```c
FLASH_If_Write_Boot_Request(BOOT_REQUEST_UPGRADE);
NVIC_SystemReset();
```

### 5.3 注意事项

- 调用 `NVIC_SystemReset()` 之前，建议先关闭或 flush 网络发送，避免复位时正在发送的数据丢失。
- `FLASH_If_Write_Boot_Request` 写 Flash 时不能被打断，调用前确保没有高优先级中断会干扰 Flash 写入。
- 如果 `FLASH_If_Write_Boot_Request` 返回失败，应通过 TCP 回复错误码，不要复位。

## 八、烧录测试 Checklist

1. 全片擦除后烧录新 Bootloader。
2. 首次启动：BOOT_SLOT_ADDR 和 BOOT_REQUEST 都是 0xFFFFFFFF，应进入 IAP 模式（TFTP 等待）。
3. 通过 TFTP 传一个 App 固件。
4. 传输完成后检查：
   - 新固件写入 spare 槽。
   - `mark_new` 成功，spare 槽 meta 为 NEW/PENDING。
   - `commit` 成功，active 切换到新槽，旧槽变为 OLD/IDLE。
   - Bootloader 复位后从新槽启动 App。
5. App 运行后发送 CMD_ENTER_BOOTLOADER 命令：
   - 应写入 BOOT_REQUEST_UPGRADE 并复位。
   - Bootloader 启动后进入 IAP 模式，等待新固件。
6. 再次升级，确认槽 A/B 交替切换。

## 九、关键设计原则

1. **永远保留一份已知可用的旧固件**：A/B 槽确保升级失败可回滚。
2. **不要从 App 跳转回 Bootloader**：用 `NVIC_SystemReset()` 冷启动最可靠。
3. **元数据修改必须经过 `meta_commit`**：任何状态切换最终都要落盘到 sector 3。
4. **启动前调用 `iap_slot_init()`**：恢复掉电残留状态，保证系统处于确定可启动状态。
