## 一、当前计划

**计划名称**：重写 IAP：软件 A/B 双备份 + Bootloader + TFTP/TCP/HTTP 三通道升级

**核心目标**：在 STM32F407VG 单 bank 1MB Flash 上实现软件 A/B 双备份，升级失败自动回滚；Bootloader 支持 TFTP、HTTP、TCP 私有协议三条升级通道；所有 App↔Bootloader 切换走 `NVIC_SystemReset()` 硬复位，避免旧版软跳转污染导致的变砖。

### 已完成的关键事实

1. **分区已确定**（见 `IAP_Flash_Layout.md`）：
   - Bootloader：0x08000000 - 0x0800BFFF（48KB，sector 0-2）
   - 标志区：0x0800C000 - 0x0800FFFF（16KB，sector 3，存 boot_request + slot_state）
   - Slot A：0x08010000 - 0x0805FFFF（320KB，sector 4-6）
   - Slot B：0x08060000 - 0x080BFFFF（384KB，sector 7-9）
   - 预留区：0x080C0000 - 0x080DFFFF（128KB，sector 10）
   - net_config：0x080E0000 - 0x080FFFFF（128KB，sector 11，**禁止擦除**）

2. **关键地址宏已定义**（在 `flash_if.h` 中）：
   - `BOOT_REQUEST_ADDR = 0x0800FFF8`：升级请求标志
   - `BOOT_REQUEST_NORMAL = 0xFFFFFFFF`：正常启动
   - `BOOT_REQUEST_UPGRADE = 0x55AA55AA`：请求升级
   - `BOOT_SLOT_ADDR = 0x0800FFFC`：槽管理结构体
   - `SLOT_A_START_ADDR`、`SLOT_B_START_ADDR` 等

3. **flash_if 已具备能力**：
   - `FLASH_Get_Sector(addr)` 动态计算 sector
   - `FLASH_If_Erase_Range(start, end)` 按范围擦除，guard 禁止擦 sector 11 和 Bootloader 区
   - `FLASH_If_Write_Boot_Request(value)` 写升级请求标志

4. **App 链接脚本已修正**：
   - `STM32F407XX_APP.ld`：`FLASH ORIGIN = 0x08010000, LENGTH = 320K`（Slot A）
   - 修正了旧版 `ORIGIN=0x08000000` 与 Bootloader 重叠的 bug

## 四、关键设计决策（必须在后续实现中保持）

### 4.1 启动方案：方案 3 —— 不清除 boot_request，由 slot_state 决定

- App 收到升级命令后，调用 `FLASH_If_Write_Boot_Request(BOOT_REQUEST_UPGRADE)`，然后 `NVIC_SystemReset()`。
- Bootloader 启动后**同时读取** `boot_request` 和 `slot_state`：
  - 若 `boot_request == UPGRADE_REQUEST` 或 slot 状态指示需要升级 → 留在 Bootloader，初始化网络栈等待固件。
  - 否则 → 10s 超时后跳转到 active VALID 槽。
- `FLASH_If_Write_Boot_Request(BOOT_REQUEST_NORMAL)` 当前实现返回 `-1`（不执行清除），这是**有意为之**。

### 4.2 双阶段提交防断电撕裂

```
ERASING → COMMIT_PENDING → COMMIT_DONE
```

- `ERASING`：开始擦除备用槽时写入。
- `COMMIT_PENDING`：数据收完且 CRC 通过时写入。
- `COMMIT_DONE`：翻转 active_slot、新槽置 VALID、旧槽置 OLD 后写入。
- 任意阶段断电重启，都能恢复到确定状态。

### 4.3 Slot A 只有 320KB

- 当前分区中 Slot A = 320KB（sector 4-6），Slot B = 384KB（sector 7-9）。
- 这是历史遗留，因为 sector 4 只有 64KB。
- 若要保持 A/B 完全对称，可考虑将 A 和 B 都视为 320KB，或调整分区让 A/B 都占 384KB（需移动起始地址，但不推荐改动已确定的 net_config 位置）。
- **建议**：先按 320KB 上限实现，后续如需扩至 384KB 再调整。

### 4.4 跳转安全

- 所有 App↔Bootloader 切换必须走 `NVIC_SystemReset()` 硬复位。
- Bootloader 中 `jump_to_app()` 仍保留裸函数指针跳转，但**只应在复位后、状态完全干净时调用**。
- 最终目标：Bootloader 决定跳转槽后，通过设置标志 + `NVIC_SystemReset()` 完成切换（若方案调整）。

### 4.5 CRC32 一致性

- 必须与现有 `tftp_server.c` 使用的以太网多项式 `0xEDB88320` 保持一致。

## 五、下一步建议（从新对话继续时）

**推荐从 `iap_slot.h/.c` 开始**，因为它是整个上层接口的根基：

1. 定义 `slot_state_t` 枚举（EMPTY/VALID/NEW/INVALID/OLD）和 `commit_state_t` 枚举。
2. 定义 `boot_slot_t` 结构体：magic、active_slot、commit_state、slot[2].{state, crc32, version, size}。
3. 实现：
   - `iap_slot_init()` — 首次上电初始化结构体。
   - `iap_slot_select_target()` — 选择备用槽（非 active）。
   - `iap_slot_commit_begin()` / `iap_slot_commit_pending()` / `iap_slot_commit_done()` — 双阶段提交。
   - `iap_slot_rollback()` — 回滚到旧 VALID 槽。
   - `iap_slot_get_boot_target()` — Bootloader 启动时选择跳哪个槽。

然后依次实现 `iap_rx` → `http_server` + `tftp_server` + `tcp_upgrade` → `bootloader_main` → `tcp_echoserver`。
