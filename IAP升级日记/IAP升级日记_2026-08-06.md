### 1. 修正 `FLASH_If_Erase_Range()` 的前进逻辑

**文件：** `Bootloader/flash_if.c`

**问题：**

原代码用 `<` 和 `>` 判断地址范围来决定擦除后前进步长：

```c
if (erase_start_addresss < USER_FLASH_FIRST_PAGE_ADDR) { +16K }
if (erase_start_addresss > USER_FLASH_FIRST_PAGE_ADDR) { +128K }
```

存在两个 bug：

1. 漏了 `==`：当地址正好等于 `0x08010000`（sector 4 起点）时，两个条件都不成立，导致死循环。
2. sector 4 实际大小是 64KB，但代码只会走 16KB 或 128KB 分支，导致 sector 边界错位。

**解决：**

新增 `FLASH_Get_Sector_Size()` 辅助函数，按 sector 编号查表返回真实大小：

```c
sector 0-3 : 16KB
sector 4   : 64KB
sector 5-11: 128KB
```

`FLASH_If_Erase_Range()` 改为循环：先算当前 sector，擦除，再按真实 sector 大小前进一步。

### 2. 确定 Bootloader 与标志区布局（方案 A）

**决策：** 把 Bootloader 从 64KB 缩到 48KB，sector 3（16KB）专门用作标志/配置区。

**原因：**

`BOOT_REQUEST_ADDR`（`0x0800FFF8`）和 `BOOT_SLOT_ADDR`（`0x0800FFFC`）原来都在 sector 3 里，但 sector 3 属于 Bootloader 64KB 范围。要清 `boot_request` 必须擦 sector 3，会同时破坏 Bootloader。

**修改：**

- `Bootloader/STM32F407XX_BOOT.ld`：
  ```c
  FLASH (rx) : ORIGIN = 0x08000000, LENGTH = 48K
  ```

- `Bootloader/flash_if.h`：
  ```c
  #define BOOTLOADER_SIZE (48U * 1024U)  /* 48KB, sector 0-2 */

  #define FLAG_SECTOR_START_ADDR 0x0800C000U
  #define FLAG_SECTOR_END_ADDR   0x08010000U
  ```

新的 Flash 布局：

| 区域 | 地址 | 大小 | 扇区 |
|---|---|---|---|
| Bootloader | `0x08000000` | 48KB | 0-2 |
| Flag/Config | `0x0800C000` | 16KB | 3 |
| Slot A | `0x08010000` | 320KB | 4-6 |
| Slot B | `0x08060000` | 384KB | 7-9 |
| Reserved | `0x080C0000` | 128KB | 10 |
| net_config | `0x080E0000` | 128KB | 11（禁止擦除） |

### 3. 实现 `FLASH_If_Write_Boot_Request()`

**文件：** `Bootloader/flash_if.c`

**学到的知识点：**

Flash 只能把 **1 改成 0**，不能把 **0 改成 1**。要把 0 改回 1，必须擦除整个 sector。

- `BOOT_REQUEST_NORMAL = 0xFFFFFFFF`：全 1，擦除后的默认值。
- `BOOT_REQUEST_UPGRADE = 0x55AA55AA`：某些位为 0，表示请求升级。

**写 UPGRADE：**

`0xFFFFFFFF → 0x55AA55AA` 只把 1 变 0，可以直接用 `HAL_FLASH_Program()`，安全。

**写 NORMAL：**

`0x55AA55AA → 0xFFFFFFFF` 需要把 0 变回 1，必须擦 sector 3。

---

### 4. 选择 boot_request 处理策略（方案 3）

**决策：** 不清除 `boot_request`。App 写 `UPGRADE` 后复位，Bootloader 启动时读 `boot_request`，但最终是否进入升级模式由 `slot_state` 决定。

**理由：**

- 方案 2（擦 sector 3 同时重写 slot_state）依赖 `iap_slot.c`，现在还没写。
- 方案 3 现在就能实现，最简单，先把整个流程跑通。
- 后续 `iap_slot` 写完后，可以再考虑是否升级到方案 2。

**调用流程明确：**

```text
App 收到升级命令
    ↓
调用 FLASH_If_Write_Boot_Request(BOOT_REQUEST_UPGRADE)
    ↓
调用 NVIC_SystemReset()
    ↓
Bootloader 启动
    ↓
读 boot_request = UPGRADE
    ↓
检查 slot_state
    ├─ commit_state == DONE 且 active_slot 有效 → 正常启动
    └─ 否则 → 进入升级模式接收固件
```

**注意：** 清 `NORMAL` 应该由 Bootloader 在升级完成后调用，而不是 App。当前方案 3 中此分支直接返回 `-1`，不使用。
